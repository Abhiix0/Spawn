## 1. Purpose and Scope

The inspection subsystem answers one question about an existing repository:
what is in it? It does not create, modify, or publish files. It does not run
repository code, resolve dependencies over the network, or validate that tools
work correctly — it only reads the filesystem statically.

**In scope for v1.1.0:**
- Shared data models, enums, and interfaces (this issue, #53).
- Safe, deterministic filesystem discovery (#54).
- Language and framework detection (#55).
- Dependency and package-manager detection (#56).
- Engineering tooling detection (#57).
- Orchestrating analyzers into a unified report (#58).
- `spawn inspect` CLI command and JSON output (#59).

**Out of scope for v1.1.0:** vulnerability scanning, dependency resolution,
semantic code analysis, running tests, executing linters, and changes to
`spawn create` or `spawn doctor`.

## 3. Finding Representation

FINAL.

```python
@dataclass(frozen=True)
class Finding:
    category:        FindingCategory
    subject:         str                   # stable, lowercase, hyphen-separated
    detection_state: DetectionState
    evidence:        tuple[Evidence, ...]
    detail:          str | None = None
```

### Finding identity

Identity is exactly `(category, subject)`. `detection_state` is **not** part
of identity. When two findings share the same identity (#58 orchestrator):

1. Keep the higher-confidence state:
   `detected > inferred > unknown > not_detected > not_checked`
2. Merge evidence: union by `path`, preserving first-seen order.

### `subject` format

Lowercase, hyphen-separated. Each analyzer documents its own subjects.
Examples: `"python"`, `"fastapi"`, `"pytest"`, `"uv"`, `"github-actions"`.

### `FindingCategory` values

| Value | Meaning |
|---|---|
| `"language"` | Programming language |
| `"framework"` | Application-level framework (not testing frameworks — those are `"tool"`) |
| `"package_manager"` | Package manager |
| `"dependency"` | One declared package (one `Finding` per package) |
| `"tool"` | Linter, formatter, type-checker, test runner, VCS, pre-commit, … |
| `"ci"` | CI/CD system |
| `"container"` | Container or orchestration config |
| `"database"` | Database or cache indicator |
| `"structure"` | Repository layout observation |

New values are additive — no schema bump. Consumers must handle unknown values
gracefully (skip, do not crash).

### Canonical ordering

`findings` sorted ascending by `(category.value, subject)`.
`analyzer_results` sorted ascending by `analyzer_name`.
`evidence` within a finding sorted ascending by `path`.
The orchestrator (#58) constructs them in this order before building the report.

## 4. Detection States

FINAL.

```python
class DetectionState(StrEnum):
    DETECTED     = "detected"
    INFERRED     = "inferred"
    UNKNOWN      = "unknown"
    NOT_DETECTED = "not_detected"
    NOT_CHECKED  = "not_checked"
```

| State | Meaning | Example |
|---|---|---|
| `detected` | Direct, unambiguous file evidence | `[tool.pytest.ini_options]` in `pyproject.toml` |
| `inferred` | Probable from indirect evidence | `fastapi` in `requirements.txt`, no pyproject framework section |
| `unknown` | Ran, found relevant files, cannot determine | Dynamic `install_requires` expression |
| `not_detected` | Checked and found nothing | No `pytest.ini`, no `[tool.pytest]`, no pytest dep |
| `not_checked` | Did not attempt | Dependency analyzer skipped — `pyproject.toml` unreadable |

### Evidence and `detail` rules (enforced by `validate_report`)

| State | Evidence | `detail` |
|---|---|---|
| `detected` | **Required** ≥1 | Optional |
| `inferred` | **Required** ≥1 | **Required** — explain inference chain |
| `unknown` | Optional | Optional |
| `not_detected` | Optional | Recommended — name locations checked |
| `not_checked` | **Must be empty** | Optional |

### Confidence precedence

```
detected (5) > inferred (4) > unknown (3) > not_detected (2) > not_checked (1)
```

Encoded in `_DETECTION_STATE_PRECEDENCE` in `models.py`.

## 5. Evidence

FINAL.

```python
@dataclass(frozen=True)
class Evidence:
    path:      str              # repository-relative, forward-slash
    indicator: str              # short human-readable description
    detail:    str | None = None
```

### `path` rules — all mandatory

- Relative to the inspection root.
- Always forward slashes regardless of OS.
- Never starts with `/` or a drive letter.
- Never contains `..` segments.
- ✓ `"pyproject.toml"`, `".github/workflows/ci.yml"`, `"src/app.py"`
- ✗ `"/absolute"`, `"C:\\Windows"`, `"../outside"`

### `indicator`

Short, human-readable; not machine-parsed.
Examples: `"[tool.pytest.ini_options] section"`, `"fastapi in [project.dependencies]"`.

### `detail`

Optional context (line number, version string, specific key). Plain string
only. No structured sub-fields in v1.0.

## 6. Diagnostics

FINAL.

```python
@dataclass(frozen=True)
class Diagnostic:
    code:     str              # "source_slug.snake_case_reason"
    message:  str
    severity: str              # "error" | "warning" | "info"
    source:   str              # analyzer slug, "discovery", or "orchestrator"
    path:     str | None = None  # repository-relative, if applicable
    fatal:    bool = False
```

### Code scheme

`<source_slug>.<snake_case_reason>`. All lowercase. Each analyzer defines its
own codes; no global registry. Examples:

| Code | Emitted by | Meaning |
|---|---|---|
| `"discovery.unreadable_file"` | `"discovery"` | File could not be read |
| `"dependency.malformed_manifest"` | `"dependency"` | Manifest could not be parsed |
| `"orchestrator.meta_unreadable"` | `"orchestrator"` | `.spawn/meta.json` unreadable |

### `fatal` semantics

`fatal=True`: source cannot continue → orchestrator sets that analyzer to
`FAILED`. A `fatal=True` from discovery sets the entire report to `FAILED`.
`fatal=False`: source recovered → status becomes `PARTIAL`.

### Diagnostic vs `not_checked` finding

A `Diagnostic` is about the analysis process. A `not_checked` finding is
about a subject that was not examined. They coexist — neither replaces the
other.

## 7. Report Status and Partial Results

FINAL.

```python
class AnalysisStatus(StrEnum):
    COMPLETE = "complete"   # ran, zero diagnostics
    PARTIAL  = "partial"    # ran, ≥1 non-fatal diagnostic
    FAILED   = "failed"     # ≥1 fatal diagnostic or unhandled exception
    SKIPPED  = "skipped"    # never attempted
```

### Per-analyzer status (set by #58 orchestrator)

| Condition | `AnalyzerResult.status` |
|---|---|
| Ran, zero diagnostics | `complete` |
| Ran, ≥1 non-fatal diagnostic | `partial` |
| ≥1 fatal diagnostic or unhandled exception | `failed` |
| Never attempted | `skipped` |

### Overall report status (set by #58 orchestrator)

| Condition | `InspectionReport.status` |
|---|---|
| All analyzers `complete` or `skipped` | `complete` |
| ≥1 analyzer `partial` or `failed`, discovery ok | `partial` |
| Discovery failed fatally | `failed` |

### Partial-result guarantee

Valid findings produced before a fatal error **must** be preserved.
The orchestrator must not discard findings from a failed analyzer run.

## 8. Analyzer Interface

FINAL. Protocol vs ABC: APPROVED by #55, #56, #57.

```python
# src/spawn/inspection/base.py
from typing import Protocol, runtime_checkable
from spawn.inspection.models import AnalyzerResult, DiscoveryInventory, InspectionTarget

@runtime_checkable
class Analyzer(Protocol):
    name: str   # stable slug, e.g. "language", "dependency", "tooling"

    def run(
        self,
        target: InspectionTarget,
        inventory: DiscoveryInventory,
    ) -> AnalyzerResult: ...
```

A plain class with `name: str` and a matching `run()` satisfies this.
`isinstance(obj, Analyzer)` works at runtime.

### `InspectionTarget`

```python
@dataclass(frozen=True)
class InspectionTarget:
    path: Path   # resolved, absolute, confirmed readable directory
```

Constructed by #58 after validation. Analyzers use `target.path` to open
files. The absolute path is **not** serialised (see §9).

### `DiscoveryInventory`

Produced by #54. Defined here so #55–#58 can compile before #54 merges.

```python
@dataclass(frozen=True)
class DiscoveryInventory:
    files:       tuple[str, ...]        # sorted, relative, posix paths
    directories: tuple[str, ...]        # sorted, relative, posix paths
    skipped:     tuple[str, ...]        # paths not traversed
    diagnostics: tuple[Diagnostic, ...] # recoverable discovery errors
```

All paths: repository-relative, forward-slash, sorted lexicographically.
#54 must produce an object satisfying this exact shape. NEEDS SIGN-OFF #54.

### Contracts on `run()`

1. **MUST NOT raise.** Catch all exceptions; emit `Diagnostic(fatal=True)`.
2. **MUST NOT modify** any file under `target.path`.
3. **MUST NOT execute** repository code or spawn subprocesses.
4. **MUST NOT** make network requests.
5. **MAY** return zero findings.
6. `analyzer_name` on the returned result **must equal** `self.name`.

## 9. Serialization and Versioning

FINAL.

### Entry points

```python
from spawn.inspection import to_json, from_dict, from_json, ReportDecodeError

to_json(report: InspectionReport, *, indent: int = 2) -> str
from_json(text: str) -> InspectionReport    # raises ReportDecodeError
from_dict(d: dict)  -> InspectionReport     # raises ReportDecodeError
```

`to_json()` returns UTF-8 JSON ending with `\n`. Byte-identical for equal
reports with the same `generated_at`. `ensure_ascii=False`.

### `target` serialisation — portable root label

`InspectionTarget.path` is an absolute runtime `Path`. It is **not** written
to JSON because the same repository can be inspected from different mount
points, making the absolute path non-portable.

`to_dict()` emits `{"root": "."}` — a stable label meaning "the inspection
root". `from_dict()` reconstructs `InspectionTarget(path=Path("."))`.
Consumers that need the original absolute path for further filesystem
operations must retain it separately when constructing `InspectionTarget`.

```json
"target": { "root": "." }
```

This resolves the portability concern raised in the pre-merge review.
FINAL.

### Top-level field order (stable)

```
schema_version → status → generated_at → target → recorded_metadata →
summary → structure → findings → analyzer_results → diagnostics
```

### List ordering (canonical)

| List | Order |
|---|---|
| `findings` | Ascending `(category.value, subject)` |
| `analyzer_results` | Ascending `analyzer_name` |
| `evidence` within a finding | Ascending `path` |
| `diagnostics` within `AnalyzerResult` | Emission order |

The orchestrator (#58) constructs in this order; `to_json` serialises as-is.

### Required fields for loading

`schema_version`, `status`, `target`. All others default to empty/`None`.

### Version gating

| Incoming `schema_version` | Behaviour |
|---|---|
| Same major, any minor (e.g. `"1.5"`) | Accepted; unknown fields ignored |
| Different major (e.g. `"2.0"`) | `ReportDecodeError` — message names both versions |
| Missing or non-string | `ReportDecodeError` |
| Malformed (not `"major.minor"`) | `ReportDecodeError` |

### Unknown fields on load

Silently ignored at every level. Enables forward-compatible reading of newer
minor versions. Consistent with `read_project_metadata()` behaviour.

### `schema_version` bump policy

| Change | Action |
|---|---|
| Add new optional field | No bump |
| Add new required field | Minor bump (`"1.0"` → `"1.1"`) |
| Rename or remove field | Major bump (`"1.0"` → `"2.0"`) |
| Add `FindingCategory` value | No bump |
| Change `FindingCategory` string | Major bump |
| Change a `subject` string | Breaking — emit old alongside new for one minor version |

### `generated_at`

ISO 8601 UTC string. Present for human reference. **Exclude from regression
comparisons** — it changes per run. Tests pop this key before comparing, same
as `created_at` in `tests/test_fixtures.py`.

### `ReportDecodeError`

Subclass of `InspectionError` → `SpawnError`, `exit_code = 7`. Raised for
invalid JSON, missing required fields, wrong types, unknown enum values,
incompatible major version.

## 10. Project Summary and Repository Structure

FINAL. Addresses pre-merge review point 1.

`InspectionReport` carries two explicit projection fields that #58 computes
after all analyzers have run:

```python
summary:   ProjectSummary      = field(default_factory=ProjectSummary)
structure: RepositoryStructure = field(default_factory=RepositoryStructure)
```

### Why explicit fields, not derived on-demand

The orchestrator (#58) has access to both the full findings list and the
`DiscoveryInventory` at construction time. Computing the projections there and
storing them in the report means:

- The CLI (#59) can render them without re-scanning findings.
- JSON consumers get a ready-to-display summary without walking the findings.
- The values are stable and versioned with the rest of the report.
- Tests can assert on summary fields without knowing the full finding set.

### `ProjectSummary`

```python
@dataclass(frozen=True)
class ProjectSummary:
    name:              str | None = None
    origin:            str        = "external"   # "spawn" | "external"
    spawn_version:     str | None = None
    primary_language:  str | None = None
    primary_framework: str | None = None
```

**Derivation rules (implemented by #58):**

| Field | Source | Rule |
|---|---|---|
| `name` | findings or directory name | `pyproject.toml [project] name` → directory basename → `None` |
| `origin` | findings | `"spawn"` iff `structure/spawn-generated` finding is `detected` |
| `spawn_version` | `recorded_metadata` | `recorded_metadata.spawn_version` when `origin == "spawn"`, else `None` |
| `primary_language` | findings | `subject` of highest-confidence `language` finding, else `None` |
| `primary_framework` | findings | `subject` of highest-confidence `framework` finding, else `None` |

### `RepositoryStructure`

```python
@dataclass(frozen=True)
class RepositoryStructure:
    top_level_files:       tuple[str, ...] = ()
    top_level_directories: tuple[str, ...] = ()
    file_count:            int             = 0
    directory_count:       int             = 0
```

**Derivation rules (implemented by #58):**

| Field | Source | Rule |
|---|---|---|
| `top_level_files` | `DiscoveryInventory.files` | Entries with no `/` separator, sorted |
| `top_level_directories` | `DiscoveryInventory.directories` | Entries with no `/` separator, sorted |
| `file_count` | `DiscoveryInventory.files` | `len(inventory.files)` |
| `directory_count` | `DiscoveryInventory.directories` | `len(inventory.directories)` |

Both projections are pure computations over data already in the report —
no additional filesystem reads, no new analysis passes.

## 11. `.spawn/meta.json` Handling

FINAL. `ProjectMetadata` boundary confirmed — see §12.

`InspectionReport` has one optional field:

```python
recorded_metadata: ProjectMetadata | None = None
```

`ProjectMetadata` is the existing `frozen=True` dataclass from
`core/project.py`. `read_project_metadata(target.path)` is the only
sanctioned accessor. It returns `None` if absent, raises `ConfigError` if
unreadable or malformed.

The orchestrator (#58) catches `ConfigError`, emits
`Diagnostic(code="orchestrator.meta_unreadable", fatal=False)`, and leaves
`recorded_metadata = None`.

### Semantics — untrusted and possibly stale

- The repository may have changed since Spawn wrote `.spawn/meta.json`.
- Analyzers **must not** use `recorded_metadata` as the basis of a `detected`
  finding. It may support an `inferred` finding with `path=".spawn/meta.json"`
  as evidence.
- The JSON field is named `"recorded_metadata"` to make provenance explicit.
- `null` when the project was not generated by Spawn.

### `ProjectMetadata` fields

| JSON key | Python field | Type |
|---|---|---|
| `"intent"` | `intent` | `str \| None` |
| `"framework"` | `framework` | `str \| None` |
| `"provider"` | `provider` | `str \| None` |
| `"spawn_version"` | `spawn_version` | `str \| None` |
| `"created_at"` | `created_at` | `str \| None` |
| `"generator"` | `generator` | `str \| None` |
| `"git"` | `git` | `bool \| None` |

## 12. Separation from Generation

FINAL. Confirms that `ProjectMetadata` reuse does not introduce generation
dependency. Addresses pre-merge review point 5.

### `ProjectMetadata` boundary analysis

`core/project.py` imports only `core/exceptions.py` and stdlib. It contains
no references to `ProjectConfig`, `plan_project`, `generate_project`, template
classes, or any generation-side type. It is a pure read-only accessor for a
JSON file on disk. Reusing it from `inspection/models.py` carries zero
generation dependency.

Verified by static analysis: `Select-String` over all of `src/spawn/core/project.py`
for generation-side names returns zero matches. The `test_boundaries.py` AST
check guards `inspection/` from importing `spawn.cli` on every test run.

### Import rules

| `inspection/` may import | `inspection/` must not import |
|---|---|
| `core.exceptions` | `core.models` (`ProjectConfig`) |
| `core.project` | `core.planning`, `core.registry` |
| stdlib | `generators.*`, `templates.*`, `utils.*`, `spawn.cli` |

### No effect on existing functionality

`ProjectConfig` and `HealthCheck` are unmodified. `spawn create` and
`spawn doctor` import nothing from `inspection/`. All 1213 generation/doctor
tests pass unchanged.

### Boundary enforcement

`"inspection"` is in the `GUARDED` tuple in `tests/test_boundaries.py`.
The test statically enforces the no-`spawn.cli` rule on every `uv run pytest`.

### #55 — Language and Framework Detection

```python
from spawn.inspection import (
    Analyzer, AnalyzerResult, AnalysisStatus,
    DetectionState, Evidence, Finding, FindingCategory,
    InspectionTarget, DiscoveryInventory,
)

class LanguageAnalyzer:
    name = "language"

    def run(self, target: InspectionTarget, inventory: DiscoveryInventory) -> AnalyzerResult:
        findings = []
        if "pyproject.toml" in inventory.files:
            findings.append(Finding(
                category=FindingCategory.LANGUAGE,
                subject="python",
                detection_state=DetectionState.DETECTED,
                evidence=(Evidence(
                    path="pyproject.toml",
                    indicator="requires-python field",
                    detail=">=3.12",
                ),),
            ))
        return AnalyzerResult(
            analyzer_name=self.name,
            status=AnalysisStatus.COMPLETE,
            findings=tuple(findings),
            diagnostics=(),
        )
```

Testing frameworks (pytest, jest) → `FindingCategory.TOOL`, not `FRAMEWORK`.

### #56 — Dependency Inspection

One `Finding` per declared package (`subject` = normalised package name).
Malformed file → non-fatal `Diagnostic`, continue, status `PARTIAL`.

```python
from spawn.inspection import (

    Diagnostic, AnalyzerResult, AnalysisStatus,

    message="requirements.txt is truncated",
    severity="warning",
    source="dependency",
    path="requirements.txt",

        name=...,           # from pyproject.toml name or dir basename
        origin="spawn" if _is_spawn_generated(findings) else "external",
        spawn_version=recorded_metadata.spawn_version if recorded_metadata else None,
        primary_language=_top_language(findings),
        primary_framework=_top_framework(findings),
    )
    structure = RepositoryStructure(
        top_level_files=tuple(f for f in inventory.files if "/" not in f),
        top_level_directories=tuple(d for d in inventory.directories if "/" not in d),
        file_count=len(inventory.files),
        directory_count=len(inventory.directories),
    )

    return InspectionReport(
        target=target,
        status=overall_status,
        recorded_metadata=recorded_metadata,
        summary=summary,
        structure=structure,
        findings=tuple(sorted_findings),
        analyzer_results=tuple(sorted_results),
        diagnostics=tuple(report_level_diagnostics),
    )
```

**Partial-result guarantee:** preserve findings from failed analyzers.

### Outcome record (implemented in v1.1.0)

Sign-offs were given by merging #54-#59 against this contract. `SCHEMA_VERSION`
and the schema are unchanged. Items marked *decision* are implementation choices
made after the original contract; the rest follows the contract as written.

| Item | Outcome |
|---|---|
| `DiscoveryInventory` shape and `skipped` | Plain path strings, sorted; deliberate exclusions and skipped links go in `skipped` (links also get an info diagnostic). Contract shape |
| `subject` strings | Lowercase slugs, listed in `supported-technologies.md`. Contract shape |
| Finding per package vs manifest | One dependency finding per package; evidence lists each declaring manifest. Contract shape |
| `PACKAGE_MANAGER` scope | *Decision:* multi-ecosystem: pip, uv, poetry, pipenv, npm, yarn, pnpm, bun |
| `TOOL` covers git; CI subject | *Decision:* git is a `tool` (`.git` detected, ignore files only inferred); CI subjects are `github-actions`, `gitlab-ci`, `circleci`, `jenkins`, `azure-pipelines` |
| Dedup / evidence merge key | *Decision:* group by `(category, subject)`, highest state wins; evidence is the union of `Evidence` items sorted by `(path, indicator, detail)` (not "union by path, first-seen order"); `detail` is the smallest non-empty detail among winners |
| Info vs warning status | *Decision:* `info` diagnostics never change status; a non-fatal warning or error makes an analyzer, and the report, `partial`; a fatal one makes an analyzer `failed`; report is `failed` only when discovery fails |
| `summary.name` | *Decision:* root directory basename only, `null` when empty; the manifest's declared name is not used |
| `spawn-generated` semantics | *Decision:* a marker only (`structure/spawn-generated`); `summary.origin` is `spawn` when it is detected, and `spawn_version` is copied from metadata only then |
| Ecosystem identity collision | *Decision (known limitation):* a pip and an npm package with the same name merge into one finding |
| `primary_*` selection | *Decision:* best `detected` finding, else best `inferred`, by evidence count then subject; may be inferred |
| `target.root` and `generated_at` | `target.root` is `"."`; `generated_at` is excluded from regression comparison. Contract shape |
| Exit codes (#59) | *Decision:* `0` complete or partial, `7` invalid root or failed inspection, `10` unexpected. The suggested `1`/`2` split was not adopted |

## Appendix B — `validate_report` Rules

`validate_report(report) -> list[str]` in `models.py`. Empty list = valid.

1. `detected` or `inferred` → `len(evidence) >= 1`
2. `not_checked` → `len(evidence) == 0`
3. `inferred` → `detail` non-empty
4. All `Evidence.path`: relative, forward-slash, no `..`, not absolute
5. All `Diagnostic.severity`: one of `"error"`, `"warning"`, `"info"`
